## Por que a flag Suite fica ligada neste processo

No commit `93efbba`, `Station:Enabled` só vale quando `Suite:Enabled` também é true. Os dois ficam true só na porta `5192`. Conteúdo, EmulationStation, inventário e avisos ficam false. O Nginx público continua mandando `/v1/suite/` para `5190`. Só `/v1/station/` vai para `5192`.

O processo `5192` precisa dos arquivos de pepper e PEM online que a Suite `5190` já usa, porque o boot recusa subir sem eles. O pepper e o PEM da Station são outros arquivos. Se forem iguais aos da Suite, o processo recusa o boot. Isso é o esperado.

1. Confira o hash da DLL que a unit `5190` executa. O valor conhecido é `93939be3153d1ae5b465406eca9f1ddcb5c85635900ea6d60aaaeb2f44d45cb1`. Se for outro, pare e escreva o hash novo no retorno. Não troque essa DLL.
2. Confira a DLL já compilada em `/home/lz-servidor/turborama-station-20261001/server/TurboRamaSuiteOnlineServer.dll`. O valor conhecido é `862323d20072d5c461c2228f0af8ef04af1a276f0e743649520a312e67cd2226`. Se for outro, pare.
3. Leia só a coluna `version` de `suite.schema_migrations`.
   - Sem `027_suite_download_notifications`, pare. Não aplique a `028`.
   - Com `028_station_android`, não aplique de novo.
   - Com a `027` de avisos e sem a `028`, aplique `migrations/suite/028_station_android.up.sql` do commit `93efbba` no banco que a API `5190` já usa. `ON_ERROR_STOP=1`. Não use um banco de restore.
4. Copie a DLL conferida para `/opt/turborama-station-20261001/`, dono `turborama-suite`.
5. Instale o pepper e o PEM Station já gerados em `/etc/turborama-suite/station-activation-pepper` e `/etc/turborama-suite/station-assertion.pem`, modo `600`, dono `turborama-suite`. Não regrave esses arquivos se já existem.
6. Crie `/etc/turborama-suite/station-5192.env`, modo `600`, com a connection string e os caminhos do pepper e do PEM online copiados da unit que já roda na `5190`. Esse arquivo não entra no Git.
7. Rode `bash docs/station-android/scripts/exportar-spki-publica.sh`. O keyId tem de ser `06b41b778041d81b5b86a115a031418e0c4b0b2bd24ec8b340e62eaa82fb5268`. Se não for, pare antes do Nginx.
8. Instale `ops/turborama-station-api.service` e suba só `turborama-station-api.service`.
9. `GET http://127.0.0.1:5192/health` precisa ser 200. `GET http://127.0.0.1:5192/ready/station` precisa ser 200. Se o ready não for 200, não mexa no Nginx.
10. Inclua `ops/nginx-v1-station.conf` nos server blocks de `app.lzgames.com.br`. `nginx -t`. Se falhar, não dê reload.
11. Reload do Nginx. A unit `5190` não reinicia.
